# 防返工基础规划

本规划补足现有“统一多源媒体契约”。目标不是提前实现全部功能，而是在第二个来源、NAS、同步、离线或首次上架前，先做会锁定数据形态和产品边界的决策。

## 审查结论

现有约束已经定义了统一分类、联邦搜索、选集、播放能力与来源隔离。仍需前置的高风险点集中在：跨源同一作品/同一集识别、家庭与设备的数据归属、来源生命周期、缓存/离线授权、可观测性与商店合规。

## P0：写第二个来源前必须决策

| 决策 | 推荐基线 | 不前置的返工风险 | 验收证据 |
|---|---|---|---|
| 作品与集身份 | 区分**作品聚类键**、**来源版本键**、**季/集键**、**播放会话键**；只能用来源键保存进度，聚类键只供展示 | 同名不同片、重制版、不同剪辑版或不同集序导致串集、串进度、串收藏 | 两个模拟来源的同名作品、特别篇、缺集与重排集合同测试 |
| 元数据权威与人工覆盖 | 保存原标题、展示标题、别名、年份、语言、地区、分级、集序来源与置信度；低置信度不自动合并 | 后期无法纠正误合并；标题改名或多语言后搜索/收藏损坏 | 可审查的合并原因与人工拆分/合并记录 |
| 来源注册与生命周期 | 来源配置版本化；声明能力、地区、授权期限、联系人、健康策略、关闭开关与迁移策略 | 某个源失效后全局页面报错；无法快速下架有风险来源 | 启用、暂停、熔断、下架、恢复五种状态的行为清单 |
| 账户、家庭与数据归属 | 默认 local-first 访客档案；成年人/儿童独立档案；同步作为可选能力，先定义设备配对、冲突规则与数据删除边界 | 后期引入登录时历史、PIN、收藏、儿童数据混淆；多设备冲突不可解释 | 数据归属表：设备、成人档案、儿童档案、家庭、云端各拥有何种数据 |
| 政策引擎 | 将授权、地区、年龄、设备、网络、来源可用性组合成统一“是否可见/可搜/可播/可下载”决策 | 策略散落在 UI、搜索和播放器，导致儿童搜索得到但不能播等不一致 | 同一条内容在目录、搜索、历史、详情、播放的决策一致性矩阵 |
| 来源契约测试 | 每个适配器都用录制且脱敏的夹具验证目录、分类、详情、选集、搜索、播放可用/受限分支 | 站点字段变化后只在用户端暴露故障；修一个源破坏其他源 | 新来源必须通过同一组契约测试，不依赖实时第三方网络 |

## P1：接入 NAS、同步或离线前必须决策

| 主题 | 前置规则 |
|---|---|
| NAS 与本地库 | 定义扫描边界、目录权限、增量扫描、文件指纹、重复文件、删除墓碑、媒体命名规则和不上传路径。NAS 凭据只在本机安全存储，索引默认本地。 |
| 缓存与数据迁移 | 为来源目录、详情、封面、搜索索引、进度、设置分别定义 TTL、刷新、失效、配额与 schema 迁移。任何可持久化对象带版本；不可回退迁移必须有备份/导出方案。 |
| 离线下载 | 仅限来源明确允许的内容；下载记录必须含来源、集键、许可/到期、清晰度、字幕、存储占用和删除原因。播放 URL 本身不持久化。 |
| 同步与冲突 | 进度采用“同一来源集键的最新有效播放位置”；收藏/稍后看使用可解释的合并规则；儿童策略、PIN 与删除操作不得被旧设备无声覆盖。 |
| 播放质量 | 定义启动耗时、首帧、卡顿、错误、清晰度切换、失效 URI 刷新和续播失败的统一事件。按来源/版本/平台聚合，不能记录完整播放 URL 或查询词。 |
| 网络策略 | 定义 Wi-Fi/蜂窝/漫游、代理、IPv4/IPv6、弱网、超时、重试、并发与带宽上限。来源重试必须限额并可熔断，防止联邦搜索放大故障。 |

## P2：公开发布前必须决策

| 主题 | 前置规则 |
|---|---|
| 内容治理 | 来源准入证据、版权/投诉入口、下架 SLA、地区声明、内容分级来源、儿童内容申诉与人工审核责任人。 |
| 隐私与安全 | 数据清单、保留期限、导出/删除流程、最小权限、传输与本机加密、依赖清单、漏洞响应、脱敏日志与崩溃报告开关。 |
| 商店材料 | 每个平台单独维护功能声明、隐私声明、截图、年龄分级、支持链接和审核测试账户/演示路径。Apple 的隐私清单与 required-reason API、Google Play 的 Data safety 均应成为发布门禁。 |
| 无障碍与国际化 | 焦点顺序、键盘、读屏标签、字幕样式、色彩对比、动态字体、RTL、长文本、时区/地区格式。TV 的选集和播放控制必须用遥控器完整操作。 |
| 发布与回滚 | Windows 先建立 canary/stable 通道、版本兼容、更新回滚、来源远程关闭开关和数据迁移观察期；不把不可逆数据库迁移与来源大改绑在同一次发布。 |
| 支持与诊断 | 用户可导出的脱敏诊断包、来源健康页、播放错误码、网络检查、反馈分类和问题关联 ID；客服不需要用户提供 cookie、密码或完整播放地址。 |

## 推荐的领域边界

```text
来源注册表 / 授权与健康
        ↓
来源适配器 → 规范化目录、详情、季/集、搜索命中、播放候选
        ↓
策略引擎（授权 / 地区 / 年龄 / 设备 / 网络）
        ↓
作品聚类与来源版本保留
        ↓
本地索引 / 收藏 / 历史 / 进度 / 可选同步
        ↓
统一分类、全局搜索、详情选集、播放会话
```

其中“来源版本”不可被聚类覆盖：展示可合并，播放、进度、许可、错误和下架必须始终可追溯到来源版本。

## 逐阶段门禁

### 第二来源门禁

- 完成 P0 六项决策，并写入 ADR（架构决策记录）。
- 用两个离线测试来源覆盖：同名不同作品、同作品不同集序、一个来源超时、一个来源仅可浏览不可播放、一个来源被下架。
- 能说明每个搜索/详情/选集/播放结果来自哪些来源及为何排序。

### NAS / 同步 / 下载门禁

- 完成 P1 数据归属、缓存、迁移、冲突与离线许可规则。
- 删除 NAS、撤销来源授权、过期离线内容和切换设备都不会留下不可访问的私人数据或错误进度。

### 公开发布门禁

- 完成 P2 内容治理、隐私、安全、可访问性、发布与支持资料。
- 做一次真实设备矩阵验证；Windows 之外的平台未验证时必须在发布范围中排除。

## 建议 ADR 清单

在 `docs/adr/` 中按编号维护，不在代码注释或聊天记录中保留这些决定：

1. 统一作品、来源版本与集身份策略。
2. 跨源聚类证据、人工覆盖与回滚策略。
3. 访客/账户/家庭/儿童档案及可选同步边界。
4. 来源准入、授权证据、健康检测、熔断和下架机制。
5. 本地索引、缓存、数据迁移、导出和删除策略。
6. 离线下载与来源许可/到期策略。
7. 播放会话、进度、选源、错误恢复和遥测最小集。
8. Windows-first 发布、更新、回滚与跨端验证策略。

## 发布合规的外部基线

- Apple 对 App 与 SDK 的数据收集和 required-reason API 使用要求隐私清单；提交前需要按依赖和实际 API 复核。[Apple Privacy Manifest 文档](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files)
- Google Play 上架（含封闭/开放/生产测试轨道）要求完成 Data safety 信息，且即使不收集数据也需要隐私政策链接。[Google Play Data safety 文档](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

这些是发布前的规划基线，不代表当前项目已经满足或适用于所有发行渠道。
