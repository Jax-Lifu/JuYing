# ADR-012: 垂直切片收敛与去伪存真演进策略 (Vertical Slice Monorepo & De-mocking)

## 状态
已接受 (Accepted) - 2026-10-21

## 背景与上下文
在项目指导文档 v0.2 制定之前，仓库在单体应用（`apps/juying_app`）中累积了大量缺乏真实协议支持的“伪完成（Mock）”实现（如 TVBox 非 CCTV 源固定 mock、未解密 TS 硬拼为 MP4、云盘假直链域名等），同时正在进行的 Monorepo 拆分（`packages/`）处于半拉子状态，导致架构断裂。
面对 v0.2 的庞大范围（双引擎、TVBox Dart 移植、DLNA DMR、AirPlay 等），项目面临继续在单体中打补丁（技术债加剧）或全盘重写（浪费既有真实资产）的分叉抉择。

## 决策
1. **去伪存真（De-mocking 强制清虚）**：
   - 彻底删除所有虚假 Mock 数据源（假云盘直链、伪离线下载拼接等）；
   - 对尚缺乏真实沙箱运行时的 TVBox 站点，在 UI 明确打上“演示/未移植”标记并实施安全阻断，严禁伪造播放数据。
2. **垂直切片（Vertical Slice）自底向上收敛**：
   - 确立首个 MVP 垂直切片为：**「libmpv 通用播放核心 + IPTV 真实直播（含 CCTV 动态 HLS）+ NAS/本地 Range 代理」**。
   - 严格落实 ADR-007，将网络、存储、代理、播放内核沉淀到独立的纯 Dart `packages/`，主应用（`apps/juying_app`）重构为仅依赖各 package 抽象的轻量 UI 壳。
3. **高阶特性按真实里程碑分步引入**：
   - Android TV Media3 第二引擎（ADR-002）、TVBox Jar 爬虫 Dart 纯语言重写（ADR-008）、DLNA DMR 接收端与 AirPlay 等高风险功能，必须在各自独立 package 内通过抓包夹具与单测验证后方可接入 UI。

## 权衡与后果
- **收益**：彻底消除虚假实现带来的预期欺骗，确保每个合入的功能在真机上 100% 真实可用；明确了架构边界与代码迁移主干。
- **代价**：短期内产品在 UI 层面暂时减少了“纸面支持的站点与功能”，优先保证质量与协议纯度。
