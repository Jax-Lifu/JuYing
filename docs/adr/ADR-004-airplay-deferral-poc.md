# ADR-004: AirPlay 接收端整体后置至 P2 并优先做 PoC

## 状态
已接受 (Accepted)

## 日期
2026-10-20

## 背景与上下文
AirPlay 属于 Apple 私有非公开协议，接收端主要依赖社区开源逆向实现（如 UxPlay、android-airplay-server）。
核心挑战包括：
1. **许可证风险**：UxPlay 基于 GPLv3 许可证，若以动态或静态库方式集成到主工程，可能引发 GPL 许可证传染风险，导致整体分发代码必须开源。
2. **协议不确定性**：UxPlay 原生不支持 AirPlay 2 视频直投，仅支持屏幕镜像与音频推流；关于 HLS 视频接力是否可用在业内存在矛盾结论。
3. **平台稳定性**：AirPlay 配对加密、mDNS 组播在多网卡与 Windows 防火墙下的表现不可控。

## 决策
将 AirPlay 接收端整体归类为 **P2** 候选特性；在 M0 阶段首先进行独立的技术验证（PoC-5），不将其纳入 MVP (P0/P1) 承诺范围。

## 原因分析与权衡
1. **降低项目阻断性风险**：
   - 避免由于私有协议逆向库的高复杂度阻碍核心流媒体播放与 IPTV/NAS 基础功能的正常交付。
2. **合规隔离**：
   - 先行咨询或评估 GPL 隔离方案（如独立可执行进程通信、或仅作为用户显式开启的实验性插件），杜绝主客户端代码库许可证污染。

## 何时重审
在 M0 阶段完成 PoC-5 技术验证报告与许可证评估结论后正式重审。
