# ADR-016: Apple 风格视觉与 Android TV 焦点系统分层落地策略

## 状态
已接受 (Accepted) - 2026-10-21 (具体化与落地 ADR-010 及 ADR-011)

## 背景与上下文
指导文档 v0.2 要求首发同时支持 Windows 与 Android（含手机、平板、Android TV），视觉参考 Apple 风格（Cupertino 基础、统一设计令牌、毛玻璃半透明、圆角与弹性动效），并强制提供低性能模式（Low Performance Mode）确保低端 TV 盒子 60fps 流畅。
由于主应用 `apps/juying_app` 存在大量遗留页面与组件，若在首发垂直切片中强行进行全量 100% 自绘重绘，将大幅推迟端到端真实可用版本的交付周期。

## 决策
1. **核心视听链路深度重构优先**：
   - 优先对核心视听高频交互路径（全屏播放器 OSD 控制条、IPTV 直播换台浮层/节目单、NAS/本地媒体文件网格）实施彻底重构；
   - 核心组件 100% 接入 `packages/ui_kit` 的 `AppleDesignTokens`，所有可交互项严格采用 `TvFocusGlow` 进行包裹，提供 Apple TV 风格的缩放高光与精确 D-Pad 导航；
   - 默认启用 `LowPerformancePolicy`：对低端电视芯片（GPU 算力受限设备）自动将开销极大的 `BackdropFilter` 实时高斯模糊降级为纯色半透明，确保 60fps 稳定渲染。
2. **次要配置管理页面渐进平滑迁移**：
   - 系统设置、源管理、配对向导等低频配置页面，优先确保遥控器 D-Pad 基础焦点连通性与字体缩放不破版；
   - 在核心视听切片打通并验证稳定后，再逐步地毯式替换硬编码颜色与旧 Material 组件。

## 权衡与后果
- **收益**：以最高密度资源攻克决定客厅大屏用户口碑的核心播放与换台体验，避免因非关键界面翻新阻塞整体交付。
- **代价**：次要配置页面在首个切片中视觉层级略显质朴，留待后续小步快跑迭代补齐。
