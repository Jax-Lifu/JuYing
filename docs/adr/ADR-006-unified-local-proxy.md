# ADR-006: 建立统一的本地网络代理出口服务

## 状态
已接受 (Accepted)

## 日期
2026-10-20

## 背景与上下文
在跨设备投屏与复杂流媒体播放场景中，常面临以下痛点：
1. **电视拉流缺失请求头**：多数智能电视的 DLNA 播放器拉取流媒体时不携带自定义 `User-Agent`、`Referer` 或 `Cookie`，导致防盗链源无法直接投屏播放。
2. **私有协议无法直接外投**：Samba (SMB)、NFS、本地存储文件无法直接给局域网其他 DLNA 设备访问。
3. **分块与随机拖动 (Seek)**：部分源或网络存储对 `HTTP 206 Partial Content` Range 分块支持不佳。
4. **HLS 清单改写**：相对路径或分片 Key 需经过重写转换方可被远端电视读取。

## 决策
在客户端内部建立微型本地 HTTP 代理服务（Local Proxy Server），作为跨端投屏、受限源播放与 NAS 本地转化的统一流量基础设施：
- `/p/{token}`：通用透传并注入防盗链请求头；
- `/hls/{token}/...`：HLS 清单改写与 Key 代理；
- `/f/{token}`：本地与 NAS 文件流式 Range 桥接。

## 安全与架构边界规范
1. **网络网卡绑定**：仅绑定局域网合法私有网卡或本地回环 `127.0.0.1`，严禁无鉴权向公网暴露。
2. **Token 生命周期**：使用强随机、一次性、具备生存时间（TTL）的令牌（UUID v4），防未授权遍历枚举。
3. **防 SSRF 校验**：严格限制可被代理的目标地址，杜绝内部端口探测或 SSRF 漏洞。
4. **按需启停**：仅在投屏或有代理播放需求时按需启动，空闲超时自动释放资源。

## 何时重审
本决策为底层流媒体通用基础设施，长期生效。
